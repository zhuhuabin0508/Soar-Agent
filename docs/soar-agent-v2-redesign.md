# SOAR 智能体 V2.0 改造设计（借鉴开源落地版）

> 状态：**设计稿，待评审后分阶段实施**。
> 前置依据：`docs/open-source-reference-survey.md`（开源调研结论）+ `docs/agent-v2-iteration-plan.md`（方向与内网约束）。
> 核心原则：**不整套换框架**，把开源成熟模式“抄”回现有 SOAR 架构；顶层交互抄可视化平台，底层引擎借代码框架。

---

## 一、确定的方向（承接调研结论）

经过开源调研与 Langflow 实测（不满足需求），确定 V2.0 组合拳：

| 借鉴来源 | 抄什么 | 落到 SOAR 哪里 |
|---------|--------|---------------|
| **n8n** | “自然语言→草稿→人审→发布”全链路；Chat Trigger 直接当对话智能体 | 新增"AI 生成编排草稿 + 草稿库 + 定稿发布"闭环 |
| **Shuffle / W5** | 安全工作流 + OpenAPI 工具接入 + 触发（领域模型） | 对齐通用工作流与封禁触发规则两套体系；统一工具接入 |
| **Dify** | Workflow(批处理)+Chatflow(对话) 双范式；应用草稿→调测→发布生命周期 | 智能体 = “对话型”与“流程型”双范式，统一发布/监控 |
| **LangGraph** | 图/状态机 + checkpoint + human-in-the-loop 审批 | 现有 Hermes 已基于 LangGraph，保留并收敛 |
| **OpenAI Agents SDK** | Guardrail（安全护栏） | 复用为工具/输出护栏 |

---

## 二、目标体验（一句话）

**运营人员（非开发者）也能：用一句话让 AI 生成智能体/流程草稿 → 可视化微调 → 发布成可对话或可触发的智能体；专业领域处理 = 选角色模板 + 勾工具 + 挂知识库。**

---

## 三、架构分层（收敛现有“智能体编排”）

把侧边栏“智能体编排”下的五个平铺模块，重组为**三层心智**：

```
执行层   智能体(对话型) · 工作流(流程型/触发)     ← 用户最终用的
能力层   工具(Tool)                              ← 可复用的动作
内容层   技能(怎么想) · 知识库(知道什么)          ← 被引用的资产
```

**对应前端导航改造**（`frontend/src/components/AppShell.jsx`）：
- 执行：智能体、工作流（含触发规则）
- 能力：工具
- 内容：技能、知识库

## 四、按痛点逐条落地设计

### 痛点1：工具杂乱、无法统一管理
- **来源打标 + 分组**：工具列表按「内置 / 自建 / 框架」徽章区分，按 code/http/framework 分组收起（借鉴 n8n 的节点分类）。
- **统一接入**：所有工具（含 Hermes 内置安全工具、framework 工具）统一入库、统一可见可管理（承接已完成的 `hermes-tools-migration-to-system`）。
- **消除 search_assets 双轨**：统一"勾选工具即生效"，`enabled_asset_types` 降级为可选范围过滤（涉及 `decision.py` / `tool_engine.py`）。
- **收敛 tool_search**：核心研判智能体默认不隐藏关键工具。
- **工具使用统计**：调用次数/失败率/最近使用，供清理死工具（内部可加 API）。

### 痛点2：知识库未启用
- 后端能力已具备（`kb_service / kb_retriever / kb_file_query` + API）。
- **内置 1~2 个开箱知识库**（如“安全响应规范”“常用研判口径”），让用户打开即有内容。
- **空状态引导**：知识库页三步建库 + AgentEditor 勾选处显示文档数/更新，未启用给引导。
- **检索可观测**：调试面板展示命中片段与来源，让用户看到“知识库生效”。

### 痛点3：搭建繁琐杂乱
- **AgentEditor（2656 行）拆为分步向导**：①基础信息 ②大脑与角色 ③挂能力(工具/技能/知识库/资产) ④行为与记忆+调试。
- **人物设定独立可复用**：用 Skill“角色设定”分类，一套角色设定可被多个智能体引用。
- **模板库**：预置“告警研判员 / 封禁决策员 / 资产分析员 / 自定义”等模板，一键创建再微调（借鉴 n8n/Dify 模板）。
- **双范式**：新建智能体时可选“对话型(Chatflow)”或“流程型(Workflow/触发)”。

### 痛点4：工作流创建没人用
- **AI 出初稿 → 审阅 → 固化**（核心，借鉴 n8n AI Workflow Builder）：
  - 用户在对话/调试里用自然语言描述流程 → AI 生成结构化编排草稿（步骤+工具节点+依赖）。
  - 前端**草稿库**：列表 + 简单编辑（可换节点/工具）。
  - **定稿**后发布为“对话智能体”或“流程/触发”二选一。
- **工作流模板库**：预置常用 SOP 模板，一键复制。
- **体系对齐**：导航上将“触发规则”作为封禁工作流的触发配置子项呈现，消除两套混淆。

## 五、数据模型与接口改动清单（草案）

| 对象 | 现状 | 改造 |
|------|------|------|
| `Tool` | 已有(52) | 增加 `source`(内置/自建/框架) 展示字段、`stats`(调用统计) |
| `Agent` | 已有(5) | 增加 `mode`(chatflow/workflow)、草稿态字段；保留兼容 |
| `Skill` | 已有(11) | 明确“角色设定”分类标准 |
| `KnowledgeBase` | 已有(0) | 内置种子内容 |
| 工作流 | 已有(1) | 草案表/草稿库、发布态；对齐触发规则 |
| 新增 | — | 编排草稿表(Draft)、发布记录、使用统计 |

> 后端主链只收敛，不推倒：`decision.py`(LangGraph) / `tool_engine.py`(Hermes) / `prompt_assembler.py` 保留，前端向导与草稿闭环叠加上去。

## 六、落地路线（分 4 个迭代，与既有方案对齐）

| 迭代 | 范围 | 验收 |
|------|------|------|
| **V2.1 统一工具** | 来源打标/分组/统计；search_assets 单轨；tool_search 收敛 | 工具可辨可搜、不再“配了不生效” |
| **V2.2 启用知识库** | 内置库、空状态引导、AgentEditor 联动、检索可观测 | 新建库即可被智能体检索、看得见命中 |
| **V2.3 向导式搭建** | 导航分层、AgentEditor 分步向导、角色复用、模板库、双范式 | 从模板一键建智能体、五步分别保存 |
| **V2.4 工作流闭环** | AI 出稿→审阅→固化、工作流模板、体系对齐、AI 生成编排 | 一句话生成草稿可保存并发布 |

> 内网约束：迭代仅改造自研代码，不引入重型外部依赖；模型走内网网关（现有 `LLMConfig.base_url`）。V2.1/V2.2 可并行。

## 七、待确认（开始动工前）

1. **先做哪条**：建议从 **V2.1 统一工具** 起步（地基，且不依赖 AI 能力、可快速见效）；或你想先体验“AI 生成草稿”这条主线（V2.4 的 PoC）？
2. **改动范围**：本次 V2.0 是“后端少量收敛 + 前端大量改造”，是否接受对 `AgentEditor.jsx` 等前端页面做较大的向导重构？
3. **内置知识库/模板素材**：需要业务侧提供“研判/封禁/资产”的真实 SOP 文档作为种子内容。
