# 讨论记录与待决点：智能体编排模式演进

> 状态：**讨论中，未定稿**。本文记录已对齐的共识、待决问题，避免重复讨论。

---

## 一、已对齐的共识

1. **平台需要两套编排并存**：
   - **死板（确定性）模式**：像工作流一样，预先配好流程 → 照单执行。适合保底、可审计、标准化场景。
   - **灵活（自主）模式**：靠提示词驱动，Agent 根据对话**自行规划、自行挑工具**。适合快捷、自适应、探索场景。
2. **Hermes 引擎已具备自主编排底层能力**：`plan`（生成目标+步骤+依赖+每步工具）、`delegate_task`（子代理委派）、`tool_search`（动态发现工具）、`clarify`（澄清）。**不是没有能力，而是缺少"模式入口"和"人机协作闭环"。**
3. **用户期望的闭环方向**：**AI 先出初稿 → 人审阅/保存 → 人工调整 → 定稿固化**。即把"灵活的现场发挥"沉淀为"可复用/可编辑的标准流程或配置"。

## 二、核心待决问题

### 1. 「初稿」做成什么产物？（最关键，决定后续设计）
- [ ] a. **结构化计划**：AI 生成步骤列表（action/tool/depends_on），人改步骤、换工具。
- [ ] b. **技能文本**：AI 生成自然语言指导，人改文字，注入智能体提示词。
- [ ] c. **工作流节点图**：AI 生成节点图，人用现有工作流编辑器拖拽调整。

### 2. 「保存/固化」到什么载体？
- [ ] 关联到某个**智能体**（作为其技能/配置）
- [ ] 存成**独立可复用的模板 / SOP**
- [ ] 转成一条**工作流**

### 3. 「编辑界面」放哪？做到什么程度？
- [ ] 最小可用：对话里 AI 出 plan 后提供「保存草稿」+ 简单可编辑面板
- [ ] 中等：独立「草稿库」，支持列表、编辑、定稿
- [ ] 完整：与工作流编辑器打通，支持全图形化调整

### 4. 两套模式的用户界面如何区分？
- [ ] 新建智能体时让用户选择「工作流型 / 自主规划型」
- [ ] 不区分，统一为一种智能体，靠配置/提示词决定行为

## 五、调研：piagent 是否适合做参考？（2026-09-17）

**结论：不适合作为本项目核心参考**，可仅借鉴其"技能/扩展"思路。

### 它是什么
**Pi Agent（pi.dev / piagent.fyi）** 是一个开源的**终端 AI 编码代理框架**（TypeScript，作者团队 Earendil Inc.），定位与 Claude Code / OpenAI Codex CLI **同类**——是给**程序员写代码用的 CLI 工具**，不是给**安全运营人员编排智能体/工作流用的可视化平台**。

核心特征：
- 激进极简主义（自称 "no MCP"），核心只 418 行左右，用最小化的系统提示词省 token。
- 靠 **skill / prompt template / theme / 扩展包** 深度自定制，通过 npm/git 分发。
- 四种运行模式：交互式、print/JSON、RPC、SDK。
- 支持 `AGENTS.md`、skills。

### 为什么不适合
- **用户群体与用途错位**：它是给开发者写代码的工具；本项目是给**攻防/资产/综合三组**做日常运营的**业务智能体平台**。
- **没有业务视角**：它没有"工作流草稿→人工优化→发布成对话智能体/条件触发流程"的闭环，也没有知识库/工具/剧本的运营语义。
- **没有可视化编排**：它主张"Ask Pi to build what you want"，面向工程师，不做运维侧低代码。

### 可借鉴的一小点（可选）
它把 `skill` 当作可分发、可复用的能力单元，与你们正在推的「技能 Skill = 方法论文本，打包给智能体」想法一致——可参考它的**技能打包/分发清单结构**，其余不必参考。

### 若要"业务智能体 + 自然语言生成编排草稿"的参考，应看
前面已调研的 **Dify（生成草稿闭环最完整）**、**Coze 扣子（技能=插件/工作流/触发器的上层归类）**、**Shuffle/奇安信/长亭（剧本+应用+触发）** 才是同赛道对标。
