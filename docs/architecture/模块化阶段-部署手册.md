| 3 | P0-② / P1-④ / P1-⑤ | `tools` 表**种子数据同步**：① `search_assets` 退役删除；② preset / framework / security 工具补 `mutating` / `risk_level` / `parallel_safe` / `deferrable` / `verification` 治理元数据 | **数据** | ✅ 启动时 `ensure_preset_tools` 自动同步（`REMOVED_BUILTIN_TOOLS` + 预设比对） | 无需手工 |

> **为什么「自动迁移」还要跑 SQL**：`ensure_columns` 只补**列**、不管**索引**；且自动迁移发生在应用启动时，而**列必须在应用起之前就绪**才最稳。SQL 全部幂等（`IF NOT EXISTS`），**重复执行无副作用**——所以部署纪律就是「**每次都跑**」。

## 三、部署步骤（按序执行）

```bash
# ① 备份（务必）
#    pg_dump 目标库；或至少备份 device_call_logs / agents 两张表

# ② 数据库迁移（先做！）
docker cp deploy/sql/p2_gateway_columns.sql       soar-postgres:/tmp/a.sql
docker cp deploy/sql/p2_3_agent_enabled_devices.sql soar-postgres:/tmp/b.sql
docker exec soar-postgres psql -U <user> -d <db> -v ON_ERROR_STOP=1 -f /tmp/a.sql
docker exec soar-postgres psql -U <user> -d <db> -v ON_ERROR_STOP=1 -f /tmp/b.sql

# ③ 部署后端（合并分支 → 重建镜像 → 重启）
#    合并 feat/modular-decoupling → main（或目标分支）
#    注意：backend-dev / worker-dev / beat-dev 三个服务**共用同一镜像** soar-backend:latest
docker compose build backend-dev          # 构建镜像（三个服务共用）
docker compose up -d                      # 自动重建 backend-dev / worker-dev / beat-dev
docker logs -f soar-backend-dev           # 期望：Application startup complete

# ④ 验证（见 四）
```

> 生产栈若用 `docker-compose.server.yml`，把上面的 compose 文件换成它即可（服务/容器同名）；**`run_lightweight_migrations` 属应用启动逻辑，与用哪个 compose 无关**。

**启动时自动完成、无需人工**：
- 容器启动先 `Base.metadata.create_all`（建缺失的**表**）；
- 应用启动 `run_lightweight_migrations` 补**列**（`agents.enabled_devices` + `device_call_logs` 的 `idempotency_key` / `correlation_id`）；
- `ensure_seed_data` / `ensure_preset_tools` 同步**种子**（含清理退役的 `search_assets` 工具行）。

## 五、回滚

| 层面 | 回滚方式 |
|---|---|
| 代码 | 回退到上一个发布 tag / 提交，重新构建镜像 |
| **数据库** | **列是「只加不删」的**（`ALTER TABLE ADD COLUMN`），回滚代码后**新列仍在**，旧代码不受影响（不会读它）→ **DB 无需回滚** |
| 索引 | 新索引对旧代码无害，可保留 |

> 因此本分支的**回滚是安全的**（向后兼容：只加列/索引，不改不删）。
