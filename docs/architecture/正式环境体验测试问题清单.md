## 🟠 High

### E-1 浏览器多次无响应 / 卡死

| 项 | 内容 |
|----|------|
| **状态** | ✅ 本地已修（2026-10-10）；正式环境未复测 |
| **结论** | 卡顿出在构建页预览对每个 token 做整页 `setState`。预览改为独立面板，正文用请求动画帧写入 DOM，工具结果在结束时再进状态。使用方确认同一智能体的预览不再拖死页面。 |
| **现象** | 正式环境中操作 Agent 编辑/调试时，浏览器页面多次出现长时间无响应（标签页卡顿或「页面无响应」提示），本地 feat 冒烟相对少见。 |
| **复现线索** | 多发生在 **Hermes 流式调试**（右侧「调试与预览」运行）或长时间停留在 Studio/编辑页；是否与并发多 Tab、长会话未确认。 |
| **怀疑原因** | ① 前端大包：生产 build 存在 **>3MB chunk** 警告，首屏与编辑页 JS 解析/执行偏重；② **SSE token 高频 `setTestResult`**：`AgentEditor.jsx` 每个 `token` 事件调用 `scheduleStreamUpdate` + `flush`，主线程 React 重渲染过多；③ 反向代理（nginx 等）对长连接/SSE 超时或缓冲策略与本地 dev 不一致，叠加前端等待时 UI 仍全量更新；④ 正式环境 LLM 慢导致流式持续更久，放大 ②。 |
| **涉及文件** | `frontend/src/pages/AgentEditor.jsx`（`handleTest`、Hermes 分支 ~783–930、`scheduleStreamUpdate`）；`frontend/vite.config.*`（分包）；部署层 nginx `proxy_buffering` / `proxy_read_timeout`。 |
| **修复方向** | 对 token 更新做 **节流/批量**（如 rAF 或 50–100ms 合并）；工具/delegate 状态与正文流分离 memo；生产 **code-split** 减轻 Agent 编辑页首包；代理对 `/api/v1/agents/*/chat` 关闭缓冲并拉长 read timeout；复现时用 Performance 录制对比正式 vs 本地。 |
| **验收** | 正式环境连续 3 次 Hermes 调试（含至少 1 次多工具调用）主线程 Long Task 明显减少，无「页面无响应」；Chrome Performance 中 `setState` 次数可量化下降。 |

### E-2 预览中看不到工具调用 / 执行日志

| 项 | 内容 |
|----|------|
| **状态** | ✅ 本地已修（2026-10-10）；正式环境未复测 |
| **结论** | 构建页预览保留调试明细：思考、状态、日志、工具参数与结果、文件。比正式对话更全。使用方确认可以按这个调试。正式环境若仍被 nginx 缓冲住 SSE，工具行仍可能到结束才出现，该项要在正式环境再看一次 Network。 |
| **现象** | Agent 编辑页右侧「调试与预览」运行后，在 **「执行日志」Tab**（或用户期望的预览区）看不到工具调用明细或日志行，尽管 Agent 可能已实际调工具并产出回复。 |
| **复现线索** | `engine=hermes`；调试走 `agentsApi.chatStream`（`channel: test`），见 `AgentEditor.jsx` ~769–773。运行后默认 **activeTab=`output`**（~767），工具列表在 **`logs` Tab**（~2587+）；需确认用户是否已切换 Tab。若切换后仍为空，则属数据/SSE 问题。 |
| **怀疑原因** | ① **SSE 事件未到达浏览器**：正式环境 nginx **未关闭 `proxy_buffering`**，导致 `tool_start` / `tool_end` 批量到达或仅在连接结束时刷新；② 后端 Hermes 路径 **主要发 `tool_start`/`tool_end`**，**`type: log` 事件稀少**（`decision.py` 有 log，Hermes executor 未必统一 yield log），UI「执行日志」区块依赖 `testResult.logs`（~2657）与 `toolCalls`（~2591）；③ 前端解析字段不一致（期望 `tool_name`/`tool_call_id`，需对照 `backend/app/agent/hermes/sse.py`）；④ `/chat` 流在 `agents.py` 会透传 chunk（~1044），但若中间层改写或压缩 SSE 会丢行。 |
| **涉及文件** | `frontend/src/pages/AgentEditor.jsx`（Hermes SSE 解析 ~813–916、`ToolCallList`）；`backend/app/api/v1/agents.py`（chat 流 ~1004–1044）；`backend/app/platform/agent_runtime.py`、`backend/app/agent/hermes/executor.py`（事件序列）；`backend/app/agent/hermes/sse.py`；部署 SSE 配置。 |
| **修复方向** | 运维：对 Agent chat SSE 路径设置 `X-Accel-Buffering: no`、`proxy_buffering off`、合适 `chunked_transfer_encoding`；后端：保证每次工具调用 **成对** `tool_start`/`tool_end` 且字段与前端一致；可选在 middleware 增加 **结构化 log 事件** 写入 `testResult.logs`；产品：调试运行结束后 **自动切到「执行日志」Tab** 或在「输出结果」Tab **折叠展示工具条**；用浏览器 Network 查看 event-stream 是否实时出现 `tool_start`。 |
| **验收** | 正式环境勾选 `check_whitelist` 等工具，调试输入触发工具后，「执行日志」Tab 可见工具名、状态、结果摘要；Network 中 SSE 在工具执行期间可见 `tool_start`/`tool_end` 行，而非仅在 `done` 后一次性到达。 |
