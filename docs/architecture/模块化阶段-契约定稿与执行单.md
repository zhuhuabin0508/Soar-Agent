## 2. 代码审核：根因分析

### 2.1 工具契约分裂成两层、互不映射

| 层 | 位置 | 枚举值 |
|---|---|---|
| 持久层 | `app/models/tool.py` `Tool.tool_source` | `builtin` / `framework` / `security` / `custom` |
| 运行时 | `app/agent/hermes/types.py` `ToolEntry.source` | `db_code` / `db_http` / `kb` / `openapi_dynamic` / `workflow` / `builtin` / `memory` / `delegate` / `persisted` |

同名字面量（`builtin`/`framework`）在两层语义不同，且无映射表。

### 2.2 治理名单混淆三套命名空间（根因）

| 命名空间 | 例子 | 会被 LLM 直接调用？ |
|---|---|---|
| **A 工作流节点类型** | `block_ip`、`device_action`、`send_notification`、`code_execute` | ❌（`node_executors.py:1515-1521` 的 `NODE_EXECUTORS`，节点执行器调用） |
| **B 智能体工具名** | `block_ip_on_firewall`、`check_whitelist`、`get_asset_info`、`get_threat_intel`、`trigger_workflow_skill`、`delegate_task`、`clarify`、`plan`、`schedule_cron`、`computer_use`、`search_knowledge_base`、`query_kb_file`、`search_assets`、`save_memory`、`recall_memory`、`query_banned_ip`、`calculate_ban_duration`、`record_ban`、`workflow_{id}_*` | ✅ |
| **C Hermes 原生遗留名** | `memory_write`/`memory_search`（SOAR 实际是 `save_memory`/`recall_memory`）、`execute_code`（实际节点类型是 `code_execute`）、`query_persisted_result`（budget 虚拟工具）、`read_file`/`session_search`/`web_search`/`web_extract` | ❌ |

**后果**：治理名单把 A/C 当 B 用，导致**真实写工具 `block_ip_on_firewall` 漏出治理链**。

### 2.3 全仓库硬编码工具名单清单（9 处，本阶段收敛目标）

| # | 文件:行 | 名单 | 问题 |
|---|---|---|---|

| 2 | `tool_result_classification.py:22-25` | `SOAR_WRITE_TOOL_NAMES` | **缺 `block_ip_on_firewall`** |
| 3 | `tool_result_classification.py:28-30` | `FILE_MUTATING_TOOL_NAMES` | **缺 `block_ip_on_firewall`** |
| 4 | `tool_result_classification.py:34-39` | `NO_EFFECT_TOOL_NAMES` | 含 `read_file`/`session_search` 等死名 |
| 5 | `tool_dispatch.py:26-35` | `_NEVER_PARALLEL_TOOLS` | 含 `execute_code` 死名、节点类型；`block_ip_on_firewall` 靠兜底才 barrier |
| 6 | `tool_dispatch.py:38-55` | `_PARALLEL_SAFE_TOOLS` / `_PARALLEL_SAFE_PREFIXES` | 含 `memory_search` 死名 |

## 3. 安全敞口（P0-③，必须先修）

真实封禁工具 `block_ip_on_firewall` 的治理缺失链：

| 位置 | 缺失后果 | 严重度 |
|---|---|---|
| `verification.py` 验证集 | **无证据链验证**，LLM 可跳过白名单/资产直接下发封禁 | 🔴 严重 |
| `tool_result_classification.py` `SOAR_WRITE_TOOL_NAMES` | `is_mutating_tool` 判 False，guardrail 不知它是写操作 | 🔴 严重 |
| `tool_result_classification.py` `FILE_MUTATING_TOOL_NAMES` | `file_mutation_result_landed` 恒 False，guardrail 认为封禁未「落地」 | 🟠 高 |
| `guardrails.py:401` | 循环时无封禁专属恢复提示 | 🟡 低 |

另两处**证据无法绑定 IP**：
- `tool_engine.py:741-746`：`tool_history` 不记 `arguments`。
- `verification.py:154-162`：`_verify_block_ip` 只查「是否调用过」`check_whitelist`/`get_asset_info`，不校验 IP 是否一致。

## 4. 对外工具契约（定稿）

### 4.1 契约主键：统一描述符 `ToolDescriptor`

作为 `ToolEntry`（`hermes/types.py:63-84`）的超集，是**唯一的运行时工具元数据权威**：

| 字段 | 类型 | 说明 | 现落点 |
|---|---|---|---|
| `name` | str | 契约主键 | 已有 |
| `description` | str | 写给 LLM 的「何时调用」 | 已有 |
| `args_schema` | pydantic\|None | 入参 schema | 已有 |
| `coroutine` | Callable | `async def execute(**kwargs) -> dict` | 已有 |
| `source` | str(统一枚举) | 运行时来源（治理唯一权威） | **收敛双枚举** |
| `tool_source` | str | 持久层来源 | 已有 |
| `tool_type` | str | code / http / framework / device | 已有 |
| `category` | str\|None | security/asset/memory/file_operations/pentest_*/… | 已有 |
| `risk_level` | str | low/medium/high/critical（写=high+） | **新增（种子声明）** |
| `mutating` | bool | 写操作（→ barrier + verification + 结果分类） | **新增（种子声明）** |
| `parallel_safe` | bool | 只读并行安全 | 已有（改为声明） |
| `deferrable` | bool | tool_search 可延迟 | 改为声明 |
| `untrusted` | bool | 结果不可信包装 | 已有 |
| `verification` | str\|None | 写工具验证策略（block_ip/device_action/…/None） | **新增（派生）** |

### 4.2 双 source 枚举映射表（`ToolRegistryBuilder` 输出时收敛）

| `Tool.tool_source`（持久） | `source`（运行时统一后） |
|---|---|
| builtin（is_preset 的 code 种子） | `builtin` |
| security（种子扫描类，如 nmap/nuclei） | `builtin` |
| framework | `framework`（executor 注入；`delegate`/`builtin` 仅展示别名） |
| custom（code） | `db_code` |
| custom（http） | `db_http` |
| —（动态） | `kb` / `asset` / `workflow` / `openapi_dynamic` / `memory` / `delegate` / `persisted` / `device`(P2) |

### 4.3 9 处名单 → 派生规则

| # | 名单 | 派生规则 |
|---|---|---|
| 1 | `WRITE_TOOLS_REQUIRING_VERIFICATION` | `descriptor.mutating == True`，按 `verification` 策略分派 |
| 2/3/4 | `SOAR_WRITE_TOOL_NAMES` / `FILE_MUTATING_TOOL_NAMES` / `NO_EFFECT_TOOL_NAMES` | `mutating` 与 `parallel_safe`（写→SOAR_WRITE；只读→NO_EFFECT） |
| 5/6 | `_NEVER_PARALLEL_TOOLS` / `_PARALLEL_SAFE_TOOLS` | `mutating`（写→barrier）+ `parallel_safe`；前缀保留为兜底 |
| 7 | tool_search 四名单 | `descriptor.deferrable`（来源+名字规则下沉为默认值） |
| 8 | framework 可见性 | framework 工具按 `agent.enabled_tools` 门控，非显式启用不注入 |
| 9 | `DELEGATE_BLOCKED_TOOLS` | 派生：`delegate_task`/`clarify` + `mutating` 写工具 + framework 入口工具 |

### 4.4 扩展性约定（防止后续大改）

- 新模块接入 = **产出一个 `ToolDescriptor`**，不改引擎、不改治理链、不改 9 处名单。
- `risk_level`/`mutating`/`parallel_safe` 是**种子声明字段**（加在 `builtin.py`/`framework.py`/`security.py` 的 dict），阶段 1 **不落新 DB 列**；用户自建工具按 `category` + 命名约定给保守默认值。
- 阶段 2 若需把 `risk_level` 显式落库，只在 `ToolDescriptor` 构建处改一个来源，治理链零改动。

### 第一步 · P0-③ 安全修复（独立先行，最小外科手术）

ctx.tool_history.append({

    "tool_call_id": tc.id,

**5.1C — 证据绑定目标 IP**（`app/agent/hermes/verification.py`）

- 新增 `_entry_ip(entry)`：优先 `entry["arguments"].get("ip")`，回退 `entry["result"].get("ip")`（result 是 dict 时）。

- `_verify_block_ip` 改写：

  - `get_threat_intel`（`require_threat_intel=True` 时）：同样绑定 IP。

**5.1D — 同步修 `tool_result_classification.py`**
- `SOAR_WRITE_TOOL_NAMES`（`:22-25`）加 `"block_ip_on_firewall"`。
